ЦЕЛЬ

Создай с нуля полностью рабочее нативное macOS-приложение MacPulse в:

/Users/Danila/Projects/MacPulse

MacPulse должен стать красивым, быстрым и настраиваемым системным монитором для Mac, ориентированным в первую очередь на Apple Silicon.

Приложение должно позволять пользователю видеть состояние Mac в трёх основных интерфейсах:

1\. информация непосредственно в Menu Bar macOS;
2\. компактная панель при нажатии на Menu Bar;
3\. полноценное приложение с Dashboard, подробными показателями, настройками и графиками там, где они уместны.

Главная идея продукта:
пользователь сам выбирает, какие показатели Mac хочет постоянно видеть, а MacPulse показывает их максимально нативно, компактно и красиво.


КОНТЕКСТ

Разработка ведётся на MacBook Air M1 с 16 GB RAM.

Xcode установлен.

Используй нативный стек Apple:
\- Swift;
\- SwiftUI;
\- MenuBarExtra или более подходящий современный native API;
\- WidgetKit;
\- Charts;
\- IOKit;
\- mach/system APIs;
\- Network/SystemConfiguration;
\- другие системные Apple frameworks, если они действительно нужны.

Не используй Electron, React, web wrapper или другой web runtime.

Проект создаётся с нуля, поэтому самостоятельно выбери качественную архитектуру, deployment target, структуру проекта и конкретные системные API.

Архитектура должна разделять:
\- получение системных данных;
\- модели метрик;
\- обновление данных;
\- хранение истории;
\- Menu Bar;
\- Dashboard;
\- Settings;
\- Widgets;
\- alerts.

UI не должен напрямую заниматься чтением системных сенсоров.

Проектируй приложение так, чтобы позже его можно было использовать не только на M1, но и на других Apple Silicon Mac.


ФУНКЦИОНАЛЬНАЯ ЦЕЛЬ

MacPulse должен стремиться получать и отображать максимально полный полезный набор реальных системных показателей.

CPU:
\- общая загрузка;

\- Performance/Efficiency cores, если корректно определяется;
\- температура;
\- power;
\- другие полезные CPU metrics, если они доступны.

GPU:
\- utilization;
\- temperature;
\- power;
\- другие достоверные показатели, доступные на Apple Silicon.

Memory:
\- physical memory;
\- used;
\- available;
\- percentage;
\- wired;
\- compressed;
\- cached, если корректно определяется;
\- swap.

Battery:
\- charge percentage;
\- charging/discharging;
\- cycle count;
\- battery health;
\- design/current/max capacity, где доступно;
\- temperature;
\- voltage;
\- amperage;
\- charging/discharging power.

Power:
\- CPU power;
\- GPU power;
\- ANE power;
\- SoC/package/total power там, где эти значения реально доступны.

Network:
\- текущая download speed;
\- текущая upload speed;
\- автоматические B/s, KB/s, MB/s;
\- активный interface;
\- Wi-Fi information, если доступно;
\- signal/link information, если доступно;

Storage:

\- used;
\- available;
\- percentage;
\- текущая read/write activity, если корректно доступна;

System:
\- модель Mac;
\- chip;
\- macOS version;
\- uptime;
\- hostname/device name;
\- другая полезная системная информация.

Thermals:
исследуй доступные thermal sensors Apple Silicon и отображай реальные значения там, где их можно надёжно получить.

Не ограничивайся этим списком.
Если во время исследования macOS обнаружишь другие действительно полезные системные показатели, которые логично добавить в MacPulse, можешь добавить их.


MENU BAR

Menu Bar является одной из главных функций продукта.

Пользователь должен иметь возможность самостоятельно выбрать, какие показатели отображаются постоянно.

Например:

CPU 18%   54°C   RAM 71%   ↓24M   ↑1.2M   7.8W

Нужно позволить:
\- включать и выключать отдельные показатели;
\- сохранять выбор между запусками;
\- менять порядок показателей, если это можно реализовать качественно;
\- использовать компактное форматирование;
\- не занимать бессмысленно много места в Menu Bar.

Продумай хороший UX для ситуации, когда пользователь включил слишком много показателей.


MENU BAR PANEL

При нажатии на MacPulse должна открываться компактная, визуально качественная панель с основными показателями.

Она должна позволять быстро оценить:
\- CPU;
\- температуры;
\- RAM;
\- Battery;
\- Power;
\- Network;
\- Storage.

Из неё пользователь должен иметь возможность открыть полноценный Dashboard и Settings.

ТОЧНОСТЬ ДАННЫХ

Это критический инвариант проекта.

Никогда не показывай fake/mock/придуманные sensor values как реальные.

Для каждого показателя выясни реальный источник данных.

Предпочитай public Apple API.

Для Apple Silicon temperature/GPU/power самостоятельно исследуй доступные IOKit/IOReport/SMC/system interfaces.

Если необходим undocumented/private interface, его можно использовать только осознанно:
\- изолировать реализацию;
\- не смешивать её с UI;
\- предусмотреть отсутствие API;
\- задокументировать зависимость;
\- не утверждать, что значение достоверно, пока оно не проверено.

Если показатель невозможно надёжно получить, приложение должно корректно показывать его как unavailable или не показывать вовсе.

Отсутствующий показатель лучше выдуманного.


PERFORMANCE

MacPulse сам должен быть лёгким системным монитором.

Не создавай отдельные бессистемные timers для каждого UI component.

Организуй централизованный sampling/update engine.

Realtime показатели должны обновляться достаточно быстро для ощущения realtime, но приложение не должно само заметно грузить CPU или расходовать батарею.

Статические и дорогие показатели обновляй реже.

Учитывай состояние UI и не выполняй бессмысленную тяжёлую работу, когда она не нужна.
